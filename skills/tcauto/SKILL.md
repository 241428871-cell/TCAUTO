# TCAUTO

仅用户明确要求使用 TCAUTO，或项目 AGENTS.md/CLAUDE.md 明确要求时启用。一次调用不自动永久启用项目。

主 Agent 直接完成任务，跑通后做必要测试。默认不创建子 Agent，不建立多角色协同、多轮审查、固定交接模板或额外验证门槛。不自动加载 tcauto-engineering 或工程习惯全文。

## Python 环境

- 所有项目的 Python 运行、脚本、依赖安装、测试和定时任务统一使用 Anaconda 管理的环境。先核实 Anaconda 安装位置，复用项目已确认的环境；需要新环境时按项目依赖创建，不默认使用 base。
- 执行前核对 `sys.executable`、`sys.prefix` 和 Python 版本。使用已核实的环境 Python 绝对路径，或 Anaconda 的 `conda run -p <环境绝对路径> ...`；不能依赖提示符或裸 `python`、`python3`、`pip` 判断环境。需用 pip 时，使用该环境的 `python -m pip`。不使用系统 Python、独立 venv、virtualenv 或 uv 管理的 Python 环境。
- 在目标项目实际使用的 `AGENTS.md`（或已有的 `Agents.md`）、`CLAUDE.md`（或已有的 `claude.md`）等项目入口记录环境；缺少这两个入口时补建，已有入口沿用原文件名。写明 Anaconda/conda 路径、环境名及绝对路径、Python 解释器及版本、依赖声明文件、创建或恢复命令、运行和测试命令。机器相关路径标注适用主机，迁移后重新核实；环境变化时同步更新各入口，避免相互冲突。
- Python 项目维护可复现的 `environment.yml` 或等效 Conda 环境声明，并在入口引用实际依赖文件。调度、子进程和可选审阅沿用已记录的环境。未找到可用 Anaconda 环境时说明缺失项，先完成不依赖 Python 的工作，不静默回退到其他解释器；安装环境仍遵循宿主权限要求。

## 可选审阅

用户要求审阅时，可创建一个审阅 Agent，检查已完成的产物并反馈具体问题；主 Agent 修复必要问题后交付。不委派实现、不派生其他 Agent、不循环审阅。
创建时显式指定已核实的主会话模型完整标识；用户最新模型选择优先，不固定型号。思考深度独立选 low、medium、high、xhigh，不使用 max、ultra。

## 定时续接

- 用户要求定时或持续工作时，使用宿主正式调度工具；Codex Desktop 使用 automation_update，优先复用当前会话 heartbeat；Claude Code CLI 使用 CronCreate 循环任务，按[Claude Code CLI 定时续接](references/claude-code-cli-continuation.md)执行。同一任务只保留一个续接入口，原位更新，不能因交接、自动暂停或故障另建时钟。按用户要求设定周期，未指定时用30分钟；工具不可用时说明限制。
- **续跑时钟只增不减有两层含义**：需要退避时可增加间隔，未经用户要求不自行缩短；任务及已授权的保存、分析、清理等收尾完成前，不提前撤销续接。它不授权延长用户截止时间，也不覆盖用户主动暂停、停止或撤钟。用户缩减或取消的工作同步移除，不能用历史待办阻止停止。
- 资源自动暂停只暂停受控工作；保留有用的观察、结果保存和排空续接。用户主动暂停则停止相应自动续接，不自行恢复。用户停止执行后取消恢复资格，只继续其已授权的保全与收尾；若用户同时要求停止调度，立即遵从。
- 提示保持精简，指向唯一最新状态入口，记录目标、工作区、当前状态、下一安全步骤、授权边界和结束条件。新要求合并进当前任务，保留未完成义务与已完成收据，旧快照不构成恢复授权。涉及 Python 时引用入口中已核实的 Anaconda 环境和执行命令；调度支持模型参数时使用已核实的主会话模型。
- 唤醒后先读最新状态，核实当前任务与进程身份，只续未执行步骤。每次唤醒都实际续接，不因距上次时间短而跳过；保持安静只指不打扰用户。无实质变化保持安静；实质完成、失败或必要用户行动才通知，同一待决定事项不反复提醒。有独立可做且已授权的工作就继续，不为等下一次时钟停工。
- 正常完成或已停止任务的授权收尾完成后，关闭并核实本任务的唯一续接，记录终态。截止到达时停止约定范围，不借收尾继续执行已过期的工作；只按有效授权处理保全和关闭。关闭后的旧 heartbeat 不得重建时钟或恢复任务。

仅在用户或更高优先级指令明确要求且工具授权条件满足时创建 goal；普通任务、定时续接和研究本身不构成创建授权。已有 goal 按有效指令同步，goal 与定时唤醒各司其职。

## 长任务与资源守卫

涉及后台长任务、资源背压、自动暂停或故障续接时，先读[续跑、资源守卫与收尾](references/continuation-and-resource-guards.md)，按任务需要采用相关部分，不额外建立通用管理平台。

- 启动前固定软高低水位、硬上限、暂存与空盘预算、暂停和恢复权限；具体数值由项目确定。触限不通过抬高上限或删减结果范围维持运行。
- 自动恢复只适用于事先授权的资源排空暂停：同一任务和进程身份仍有效、原因已解除、低水位与余量满足，且通过原守卫同步恢复。异常暂停或待用户决定状态不会因读数回落自动解除。
- 已完成步骤与提交收据持续保留，不重复启动、编译、全量验证或重做成功步骤。故障仅处理当前失败范围；活动 worker 不执行故障重启式 recover，资源暂停则按上条恢复原进程。控制请求超时不等于任务失败。
- 保存、上传、分析消费和精确回收各有完成条件。未知引用继续保留，停止或失败只交付部分结果，不能套用成功收尾。内存问题先区分持有者与内存类别，再做有证据的最小处理。

# Claude Code CLI 定时续接

适用于 Claude Code CLI 会话：用户要求定时续跑或持续工作时使用。用户的最新要求优先。Codex Desktop 仍按 SKILL.md 使用 automation_update。这里只写通用规则；具体周期、状态入口和授权边界来自当前项目。

## 工具与限制

- 用宿主的 CronCreate 建循环任务（recurring），用 CronDelete 删除，用 CronList 核对。ScheduleWakeup 只用于用户本人以 /loop 启动的动态节拍，不拿来代替续接时钟。
- 任务只存在于当前 Claude Code 进程中，进程退出即消失。循环任务 7 天后自动到期（最后触发一次后删除）。任务只在 REPL 空闲时触发，正在执行的回合结束后才会轮到它；宿主还会给每个任务加一个固定偏移。
- 因此要在项目唯一状态入口里记录：job ID、cron 表达式、设计说明、最近一次续接时间、暂停标记。新会话开始时，或任务快到期时，按记录原位重建：先建新任务，再删旧任务，然后更新记录。不保留两个时钟，也不留没有时钟的空档。
- 优先用循环任务，不用一次性接力。一次性接力依赖每次唤醒都记得预约下一次，漏一次就断了。

## 周期服务于缓存窗口

- 用户设定周期，是为了让下一次会话在云端提示缓存的保留期内接上。最大间隔必须小于缓存窗口：用户要求 30 分钟内接上时，用 25 分钟。
- cron 无法跨小时表达均匀的 25 分钟周期，要用分钟列表，例如 `4,29,54 * * * *`：间隔是 25/25/10，最大 25 分钟。避开 :00 和 :30。其中较短的间隔是表达式的限制，不算擅自缩短周期。
- **每次唤醒都必须实际续接**：先更新最近续接时间，再读状态、核实身份、推进下一个未完成步骤。不能设“距上次不足 N 分钟就跳过”之类的规则。“没有实质变化就保持安静”只是不打扰用户，唤醒本身照常执行。

## 提示词

- 提示词在创建时就固定了，宿主没有原位修改的接口。授权边界、步骤序列或用户规则一变，就用新提示词重建任务（先建后删），避免旧提示词带着过期的限制或授权。
- 提示词要精简，写清：唯一状态入口、每次都必须续接、当前步骤序列、运行地点与授权边界、暂停规则、通知规则。进程身份和进度留在状态入口，不写进提示词。

## 等待长任务

- 远端或后台长任务还没结束时，先做已授权、不依赖它结果的工作，不要结束回合干等。
- 要在任务结束时立刻接续，就用后台命令（run_in_background）做只读轮询，任务一结束轮询就退出，宿主会马上唤醒会话；续接时钟只作兜底心跳。不轮询输出文件，不用前台 sleep。

## 卡在用户决定时暂停时钟

- 用户要求：卡在需要用户审批或指定的事项上，没有其他已授权、可以独立推进的工作，也没有运行中的任务或后台等待需要看护时，暂停续接，避免空转。
- 做法：用 CronDelete 删除循环任务；在状态入口记录 paused=true、原因、待用户决定的事项和恢复方式；通知用户一次。用户回复后，由会话按记录重建时钟。
- 这是用户指定的暂停，不是任务终止：未完成的义务和已有收据照常保留。只要还有运行中的任务需要看护，就不暂停。

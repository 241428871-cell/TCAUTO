# TCAUTO 工程习惯

仅在用户明确要求使用 TCAUTO（包括 `$tcauto-engineering`），或目标项目 `AGENTS.md`／`CLAUDE.md` 明确要求启用 TCAUTO 时激活。新建项目、普通工作、长任务、自动研究或仅提及跨项目工程习惯均不自动激活；未满足条件时不执行后续流程。本激活规则覆盖原文中无条件读取、默认持续工作和多 Agent 的旧入口要求。

激活后读取 [跨项目工程习惯原文](references/跨项目工程习惯.md)，再读取当前项目入口与交接。将适用约定用于实际工作，不把历史示例、计划或来源项目的授权当作当前任务授权。

原文来自用户指定的《跨项目工程习惯(4).md》，按字节保留，不改写、不删节。原文提及的项目专题路径是该项目的例子；按目标项目实际位置解析，不要求复制来源工程的目录或状态。

当前流程默认由单 Agent 以尽快完成任务为目的直接推进；只有用户明确要求或任务过于复杂才使用最少必要的多 Agent。先完成全部内容并跑通主要流程，再设计和执行必要测试；实现期间仅做跑通所必需的基本检查与排障，不增加过多保护性验证。本规则覆盖原文中默认主动委派、多轮审查及前置扩展验证的旧流程；原文副本仍保留原样，权限边界及明确验收要求仍适用。

项目入口按当前任务需要维护。只有用户明确要求项目长期采用 TCAUTO 时，才在 `AGENTS.md`／`CLAUDE.md` 写入启用指令；一次调用不自动把项目设为长期启用。已有项目沿用入口和目录，不制造重复文档。

长任务、自动研究及 goal 更新、定时续接与多 Agent 审查转到同一技能集的 `tcauto`。创建子 Agent 时必须显式填写 `model` 为已核实的主会话当前模型完整标识，不省略或依赖默认继承；用户另有最新明确模型选择时按其执行。思考深度独立按任务仅选 `low`、`medium`、`high`、`xhigh`，不使用 `max`、`ultra`；用户最新要求优先于原文中的历史示例。
